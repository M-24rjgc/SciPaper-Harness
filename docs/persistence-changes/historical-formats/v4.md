# Session V4 persistence format

English | [中文](v4.zh.md)

## Summary

Inspect the complete V4 persistence inventory at `dsh-v0.1.7-rc.2`. The header records a local working directory without execution identity; tool results use tool-role messages, and message sources use named producer kinds. The V5 writer adds execution identity to the header while retaining V4 event framing.

<a id="evidence"></a>
## Source evidence

The source is the `dsh-v0.1.7-rc.2` tag. Its writer constant is 4, and all 62 root digests in its generated persistence inventory match the pre-V5 checkout inventory. The archive command retained those roots and their reachable declared types and removed source line numbers. The tag identifies this schema checkpoint; [format status](../../session-format-status.md) owns release and migration status.

Declarations come from `packages/core/session/src/types.ts`, `packages/session/session-persistence-jsonl/src/format.ts`, and first-party `SessionEventMap` merges with their reachable types. Source paths in the generated tables refer to that checkpoint without line numbers.

<a id="characteristics"></a>
## Format characteristics

- `SessionHeader.version` is 4. Logical and physical headers require `isSeeded`; `cwd` is an optional Host-local absolute path, and there is no execution identity.
- Tool results are tool-role messages with direct content and a call id. Message sources use named kinds rather than a plugin wrapper; native V4 admission validates the resulting relationships.
- Assistant streams remain embedded in message or attempt events. The physical body retains the released V2 row and compact-run framing used by the [V4 codec](../../../packages/session/session-format-v3-to-v4/src/codec.ts).

The [V3-to-V4 format specification](../../../packages/session/session-format-v3-to-v4/README.md#v3-to-v4-specification) defines historical conversion and native V4 admission. Schema types alone do not define event ordering or restoration behavior.

## Verification and limitations

The tag inventory and pre-V5 checkout inventory have identical root digests. `verify-persistence-formats --archive 4` retained all 62 roots and 586 reachable declared types. The schema describes one selected V4 checkpoint; same-version optional changes can yield other valid V4 inventories. It does not prove runtime codec admission or migration safety.

```sh
pnpm run verify-persistence-formats
```

The verifier checks every format through the checkout writer, bilingual declarations, schema completeness, and generated tables. See the [format index](README.md) for maintenance and the [current catalog](../../persistence-catalog.md) for current declarations.
