# Agent Note: Knowledge items as links in the assistant's reply

Status: implemented

[English](2026-10-02-knowledge-links-in-assistant-text.md) | 中文

## 问题

[对话视图和工具卡片上的小标签](2026-10-02-knowledge-graph-turn-trace.zh.md)展示了 agent 在一轮里碰过什么，但用户读的是回复，agent 在回复里用文字提到的正是同样的模式、论文和关系。设计要求把这些名字做成回复里的小标签：用到的节点是青色标签，用户标成不相关的节点加删除线，关系是蓝色标签，点击后在对话视图里聚焦对应节点。第一版画不出来，因为共享的 Markdown 渲染器只保留 HTTP(S)、mailto 和本地文件链接，它的 delegate 也没有让某个功能认领别的协议的办法。这些小标签还不能成为不可信的模型文字产生可点击链接的途径，不能成为 agent 从未碰过的东西的点击目标，也不能与用户的标注不一致。

## 决策

**agent 写一个带 `kg:` 协议的普通 Markdown 链接，功能通过 keyed slot 认领这个协议。** `[MoBA](kg:ai:paper:42)` 带的是各个知识视图已在用的 id：标注的 id（`<graph>:<kind>:<id>`）、关系实体的 id（`method:fixed-blocks`）或关系的 id（`compares-with:method:a>method:b`）。这几类 id 互不重叠，所以协议后面直接跟 id，不需要类型前缀，模型照它读到的原样抄写。

**渲染器把被丢弃的链接交给 owner，自己绝不为它们生成 anchor。** `MarkdownDelegateProvider` 新增 `renderSchemeLink(link, fallback)`。在落定文本中，凡是协议白名单会丢弃、协议既不是 HTTP(S) 也不是 mailto、又不是本地文件的链接，都会连同小写协议、作者原样书写的目标和链接的纯文本交给它，它返回的节点替代链接内容被绘制。没有 provider，或 provider 返回 `fallback` 时，输出与以前相同：链接的内容。流式文本不会被提供，因为冻结的块会缓存元素，而消息增长期间 owner 的解析结果可能变化；小标签在消息落定后出现。`fileMentions` 和 `pathImages` 词表遵循同样的只在落定后生效的限制。

**ui-chat 声明 keyed slot `conversation.message.link`。** 聊天视图给 delegate 一个回调，用协议作 `entryKey`、链接作 owner 值、链接内容作 `fallback` 去渲染这个 slot，所以没有单元认领的协议照旧绘制。单元是注册的组件，因此能拿到标准的 session hook 和自己的 `inject` 面；返回纯数据的解析函数给不了这些，而小标签画出之后还要跟随聊天和标注。ui-research 注册键 `kg`。

**slot outlet 在段落内绘制 `span`。** 每个渲染位置都被一个不影响布局的锚点元素包裹，即 `div`，而 `p` 里的 `div` 是非法嵌套，React 在开发构建里会报错。`renderSlot` 接受 `inline: true`（ui-slots 的 `RenderOpts`，ui-renderer 里选择锚点元素），聊天视图设置了它。

**只有当前对话自己的调用碰过的 id 才有小标签。** 单元通过 `useChat` 读取对话，在已加载各轮的知识调用里由新到旧查找，取第一个已落定且成功的 `research_knowledge` 调用，其轨迹里以节点或关系的形式包含该 id（`linkValues.ts`）。编造的 id、其他对话的 id、格式错误或为空的目标，以及失败的调用，都把链接标签画成纯文本，没有链接也没有样式。目标只按精确 id 查找（带转义时也按百分号解码后的形式查找），绝不会被跟随。查找是带相等判断的 selector，所以小标签只在它所指的内容变化时才重新渲染。

**小标签的样子由此刻的标注决定。** 图谱节点在用户此刻的标注把它标成不相关时加删除线，被钉住时带描边，用户暂停 agent 遵守标注时为普通样式，来源和规则与工具卡片的小标签相同（`verdictOf`）。单元读取共享的标注 store，在小标签指向图谱节点时读取一次标注，研究记录变化时再读一次，因为 agent 通过自己的调用打标注，store 看不到。关系的小标签为蓝色。小标签是真正的 `button`，有可访问名称（`MoBA，已钉住`、`关系：…`）和说明该 id 是什么的 title，中英文均有。

**点击后在碰过该 id 的那次调用上打开对话视图。** 它调用工具卡片小标签所调用的同一个 `openKnowledge({ call, node })`；关系的点击聚焦它的第一个端点。小标签显示 agent 自己的措辞，因为那样在句子里读起来顺畅，title 显示轨迹所记的名字，所以标签与 id 不符时看得出来。

**模型被告知怎么做，而且它能引用的每个 id 都在它读过的结果里。** `research_knowledge` 的描述和 `research-knowledge` 技能说明：把条目写成 `[name](kg:<id>)`，只用本对话中某次调用返回过的 id，绝不编造，否则把名字写成纯文本。召回结果给每个模式和论文一个 `link`（`kg:<graph>:<kind>:<id>`，与轨迹节点 id 由同样的部分拼成）；标注列表本来就带每条标注的 `id`；邻域本来就在方括号里列出每条关系的 id，路径文本现在每一跳列出一个；实体的 id 是关系 id 里的 `<from>` 或 `<to>` 部分。没有其他结果改变。

## 考虑过的替代方案

**在回复里猜名字。** 回复是模型的措辞；匹配名字会为 agent 没用过的节点画出小标签（[此前已否决](2026-10-02-knowledge-graph-turn-trace.zh.md)）。

**让净化器放行 `kg:`。** 那样渲染器就会用不可信的文字生成可点击 anchor，每个功能协议都要改渲染器。白名单保持封闭；被丢弃的链接变成什么由 owner 决定，渲染器不让任何东西可点击。

**像 `fileMentions` 那样在 delegate 里放解析函数。** 解析函数返回描述，由渲染器绘制。它被调用之后无法跟随标注或聊天，因为 props 对象里的函数没有订阅，组件也不得自己订阅，所以撤销标注后小标签会过时。

**用 Cordis service 告诉聊天哪些协议被认领**（如同 `chatKnownFilePaths` 告诉它哪些文件已知）。它能让未被认领的链接的 DOM 与以前完全一致，代价是每个功能多一次注册。slot 的 `fallback` 已经把未认领的链接画成它的文字；留下的唯一痕迹是外面一个惰性的 `span`。

**在段落里用 `div` outlet。** 浏览器里能用，但在开发构建里会报非法嵌套错误，复制或重新解析 HTML 时会把段落拆开。

**加 `kg:relation:<id>` 这样的类型前缀。** 三类 id 不会冲突，前缀只会让模型多一个出错的地方。

**画轨迹所记的标签，而不是 agent 写的。** 短名字在句子里读起来顺，而轨迹里的标签是整篇论文的标题；title 属性显示轨迹所记的名字。

## 后果

落定的消息里，带有无人认领协议的链接（`ftp:`、`javascript:`、编造的协议）现在在链接文字外有一个带 `display: contents` 的惰性 `span`；文字、布局和没有链接这一点都不变。没有这类链接的消息与以前渲染完全一样，渲染器已固定的 DOM 样例不受影响。

每个小标签在每次聊天变化时都对已加载各轮运行一次 selector。找到的 id 在其调用处停止；编造的 id 会扫描整个已加载窗口。成本随小标签数和已加载工具行数增长，长对话里小标签很多时就该加索引。

一个功能拥有一个协议：以 `kg` 注册的第二个单元会替换研究的那个。更早对话的回复，或已加载窗口没有回溯到碰过某个 id 的调用时，该链接显示为纯文本。关系的小标签只聚焦它的第一个端点，超出图中所绘十四个节点的节点不在图里，所以它的小标签打开视图时没有选中任何东西。

默认的召回结果，十六项中每项增加约十个 token，一条路径每一跳增加约十个。描述和技能各增加一小段。工具 schema 位于请求开头，只随构建变化，所以同一构建内前缀保持可复用。

由以下测试固定：渲染器的测试（提供什么、不提供什么、流式、转义、标签）、ui-chat 对 slot 调用的测试、渲染器对行内 outlet 的测试、研究对查找、小标签及其注册的测试、主机对 id 和描述的测试；并在带有已录制对话的研究主目录副本上运行产品，中英文各一遍：四种小标签样子、编造的节点、编造的关系和 `javascript:` 链接显示为纯文本、点击和 Enter 键聚焦节点，以及小标签随暂停开关和撤销的标注变化。
