# Agent Note: What a knowledge call touched, and the Conversation view

Status: implemented

[English](2026-10-02-knowledge-graph-turn-trace.md) | 中文

## 问题

知识图谱标签页能展示整张图，却没法展示 agent 在用户正在读的这一轮里用到了什么。工具卡片只写出调用的名字（一次召回、一次读取标注、一次找路径），再没有别的，所以用户看不出一次召回返回了哪些研究模式或论文，哪些标注影响了它，一次找路径又走过哪些关系。同一轮的三处展示（卡片、对话旁的图、标注列表）必须对节点的身份取得一致，而且用户改了标注之后，图仍然要是对的。需求还要求把用到的节点作为小标签放进回复文字里。

## 决策

**轨迹是随工具结果保存的投影，不是随研究保存的。** 每次 `research_knowledge` 调用，都用它本来就算出来的结构化值生成一份 `KnowledgeTrace`（版本 1）：召回结果以及 `KnowledgeBase.recall` 返回的条目、标注列表、关系邻域或路径页。工具把它声明为 `output.presentationMeta`，工具运行时把它作为 `meta` 持久化在 `tool/result` 记录上，对话界面把它作为 `ToolResultNode.meta` 提供。模型看不到它：渲染函数会从返回的文字里去掉 `knowledgeTrace`，`meta` 也不属于发给模型的内容。除了会话日志，不写任何别的地方，所以轨迹与它所描述的调用同生共死，没有 `meta` 的旧调用照旧渲染，回放也不需要旁路文件。

**只有 agent 的调用才留下轨迹。** 用户自己的命令（从桌面端运行的同样的 action）不返回 `knowledgeTrace`，所以图里画的是 agent 碰过的，从不是用户做过的。

**结构。** 轨迹有 `action`、可选的 `query`、`nodes`（`id`；`source`，取 `ai`、`project` 或 `relations`；`kind`；截断为 80 个字符的标签；`use`，取 `pinned`、`recalled`、`skipped`、`centre` 或 `end`；以及内置图谱论文的 `index`）、`edges`（关系的 id 和类型、两端、记录者，以及找到的路径上某一跳的 `walked`）、列表读取到的 `marks` 数量和是否遵守的开关、`paths` 的数量，以及 `omitted`。它最多保存 40 个节点和 80 条关系，其余计入 `omitted`，一条关系只在两端都保留时才保留。重复出现的节点只算一次，位置取第一次出现的地方。

**id 沿用各个视图已经在用的。** 研究模式或论文的 id 就是它的标注 id，即 `<graph>:<kind>:<id>`（与图谱视图作为节点 id 的字符串相同）；关系实体和关系的 id 就是关系图里的 id。想法节点是客户端唯一自己造出来的 id，而且从不保存。所以轨迹与用户的标注、与关系视图之间靠字符串相等就能对上，客户端再按标注此刻的状态取每个节点现在的判断。轨迹记录调用用到了什么（`pinned`、`skipped`），客户端画的是现在为真的：标签的删除线来自当前的标注，所以撤销或之后再标注，它仍然是对的；用户暂停 agent 遵守标注时，标签就是普通样式。

**一个注册表 symbol，因为主机把引擎加载了两次。** `recall` 把它列出的条目（图谱、序号、id、标签，以及让它们移动的标注）放在结果旁边而不是结果里面，这样模型看到的 JSON 保持原有字段。最初用的是模块级的 `WeakMap`，它在所有单元测试里都能工作，在产品里却什么也返回不了：打包后的入口和未打包的图谱插件各自加载一份 `knowledge.ts`，入口的 map 里从来没有插件的结果。现在这些条目放在一个不可枚举的属性上，键是 `Symbol.for('@deepseek-ai/dsh-research-workbench/recall-returned')`，两份模块都能读到；JSON 和对象展开会跳过它。给地图的召回历史提供数据的 `builtinIndices` 仍然用 `WeakMap`，会遇到同样的问题；本 note 记下这一点，没有改它。

**对话视图读的是对话，不是研究。** 知识图谱标签页通过标准的 `useChat(selector, equal)` 钩子拿到会话的对话，查看最近 12 轮，取最近一个有 `research_knowledge` 调用的那一轮（或者打开它的那张卡片所在的那一轮）的调用，把它们的轨迹合成一张图：想法（召回的查询）、节点和线，线分为：走过的（想法到召回中每个被钉住的条目，或找到的路径上的一跳）、普通的（读到了）、蓝色虚线（用户记下的关系）和灰色虚线（被标注排除）。图最多画 14 个节点，并说明有几个没画出来。它的布局是节点的纯函数（连接最多的节点或想法放中间，环形分层，并用固定的转角避开重叠），所以同一轮每次画出来都一样。用户的标注、让 agent 遵守的开关和每一个撤销，用的是领域地图用的那些命令；客户端把标注放在一个由这些命令更新的小型实时存储里，示例研究显示它们并拒绝一切修改。

**「在图谱里看」链接打开的就是这次调用所在的那一轮。** 有轨迹的调用的卡片带一个链接，用 `{ call, node }` 把知识图谱标签页打开到对话视图，并圈出这次调用碰过的节点；没有轨迹的调用的卡片保留原来的「查看图谱」按钮。调用属于较早的一轮时，视图会说明这一点，并给出回到最新一轮的办法。

**小标签画在工具卡片里，也据同样的轨迹画在回复文字里。** 知识工具的卡片把本次调用的节点画成工具行下面的小标签（被钉住的是描边，被标成不相关的是删除线，最多八个并标出其余的数量），每个标签都会在对话视图里聚焦它的节点。agent 自己的回复把条目写成 `kg:` 链接，渲染器把它交给研究功能，由研究功能按这些轨迹解析每个 id；[这项决策](2026-10-02-knowledge-links-in-assistant-text.zh.md)记录了链接协议、渲染器的扩展以及模型被告知的内容。

**工具行写出碰过什么。** 有轨迹的调用的那一行，数量取自轨迹（`读取你的 3 条标注`、`从你的想法出发，沿 2 条路径找基线`），没有轨迹的调用照旧显示。

## 考虑过的替代方案

**把轨迹存进研究记录或某个文件。** 它会比调用活得更久，需要清理，同一个事实还多了一个会过时的地方；用 `meta`，会话日志是唯一的存储。

**在客户端解析结果文字来重建轨迹。** 文字是给模型看的，会随工具措辞变化；而结构化的值在主机上本来就在手边。

**把调用用到了什么放进模型的结果。** 每次调用都会为模型用不上的字段花 token。

**把用户的判断记进轨迹。** 下一次修改后标签就会与标注不一致；轨迹记录调用用到了什么，判断由客户端按现在读取。

**用力导向模拟画图。** 每次运行结果不同，无法测到固定的结果；确定性的布局可以。

**以结果对象为键的 `WeakMap`。** 见上文：模块被加载两次时它会失效。

**从回复文字里解析标签。** 回复是模型的用词，在其中匹配名称只是猜测，猜错了就会为 agent 没用过的节点画出标签。agent 带着读到的 id 写下的链接则不是猜测。

## 后果

一次知识调用现在会在会话日志里带上最多几 KB 的 `meta`。本次改动之前写下的会话在对话视图里什么也不画，并保留旧的卡片；视图的空状态会说明还没有用过。

地图或关系插件开启时才提供对话视图。标注卡片需要图谱引擎，补充的关系需要关系图，所以各自只在对应的插件开启时出现；关闭的插件隐藏它的那部分，不会抛错。

客户端在知识图谱标签页里读取会话的对话，所以视图会随每一轮结束而更新，不需要命令。代价是每次对话变化都要跑一次覆盖最近 12 轮的选择器；没有变化时它返回同一个列表，所以不会重新渲染。

回复里的小标签只和它们所据以解析的轨迹一样新：在保存轨迹之前写成的会话没有轨迹，指向对话中没有任何调用碰过的 id 的链接则是纯文本。

由 `knowledge-trace.spec.ts`（构造函数及其上限）、召回、工具和加载器的测试（真实工具旁的轨迹，以及从模型文字里去掉它）、读取、合成和布局轨迹的客户端测试、对话视图和卡片的测试，以及在两种语言下用录好的对话运行产品，共同固定。
