# Agent Note：由 agent 布局、由脚本保持最新的实验看板

Status: implemented

[English](2026-09-24-research-experiment-board.md) | 中文

## 问题

远程 GPU 服务器上的长实验一直靠人工盯。一个自己跑队列的项目手写了一套看板：本地桥接服务经 SSH 登录，运行项目专用的采集脚本，画出各折进度、训练曲线、论文表格和 GPU 占用。工作台没有这样的东西。一次运行只在退出时报告指标，运行卡片只显示已用时间对比时限，也看不到机器状态。让 agent 盯着并转述数字，每看一次都要花一次模型调用；而折、轮次这类固定字段适合某个研究领域，换一个领域就不适用了。

## 决策

工作台的实验标签页是一块看板，分为固定部分和由 agent 负责的布局，上面的每个数字都由脚本读取，从不经过模型。

- **固定部分。** 每个项目都有：按状态统计的运行、每个在跑的运行及其进度、预计剩余时间和曲线、每台实验机器，以及所有运行（含命令、指标和曲线）。对话标题栏和每张运行卡片都能打开看板。
- **agent 布局，不固定字段。** `research_board` board-update 把由八种积木（`stats`、`table`、`chart`、`list`、`runs`、`text`、`kv`、`log`）组成的分区保存在 `.research/board/board.json`。值要么固定，要么按 id 或按名称和种子跟随运行。页面对着实时的项目记录解析它，所以运行一结束，表格对应的格子就填上，不需要新的读取，也不需要 agent 再做一轮；同一名称有多个已完成的种子时，显示均值和样本标准差。agent 只在计划或结论变化时修改布局，不是每跑完一次就改。
- **进度记录。** 运行把 JSON 行追加到 `$RESEARCH_PROGRESS_PATH`。监督进程的状态把最后一行带进运行记录，运行卡片借助已有的观测就能显示真实进度。看板用整份文件画曲线：本地运行直接读取，远程在跑的运行由探针读取，远程运行结束后读取取回本地的副本。
- **机器探针。** 一个只用标准库的脚本在每台主机上各运行一次，经 SSH 或在本地。它通过 `nvidia-smi` 报告 GPU，报告处理器和内存占用（有 cgroup 配额和上限时按配额和上限计算）以及磁盘。每次读取都往六小时的历史里加一个采样点。
- **采集脚本。** 只有这个项目读得到的内容，比如用户自己在服务器上启动的队列，由 agent 写一个只读的 Python 脚本来读。看板打开期间用某个环境的解释器运行它，脚本打印 `{stats?, sections?, alerts?}`。它运行时不弹出审批，与 agent 的实验一样。解析不了的部分会被丢弃并指明，其余部分照常保留。board-refresh 立即运行所有采集脚本并报告每个错误，agent 几次调用就能把脚本修好。
- **读取不经过模型。** 看板打开期间，页面每十五秒请求一次；服务最多每十秒启动一次后台读取，同时只进行一次读取，并把结果保存在 `.research/board/snapshot.json`，供重新打开的看板使用。

## 影响

- 看板开着时，每十到三十秒对每台实验主机发起一次探针调用，并运行一次到期的采集脚本；看板关着时不发起任何调用，所以 GPU 历史会有空档。
- GPU 读数依赖 NVIDIA 的 `nvidia-smi`；在 macOS 上不读取处理器和内存占用。
- 采集脚本是平台在用户服务器上反复运行的项目代码。它在项目里可见，受两分钟超时和 4 MB 输出上限约束，只在看板打开或 agent 请求时运行。
- 实验标签页里手动提交运行的表单移到了看板下方，默认折叠。
- [科研工作台以对话为主的界面](../feature/2026-09-21-research-workbench-conversation-first-surface.zh.md) 描述的标题栏工具按钮，在项目文件夹旁边多了一个看板按钮。

## 考虑过的替代方案

**让 agent 维护看板上的数字。** 每次刷新都要花一次模型调用，花费的 token 随看板大小增长，数字也只和最近一轮对话一样新。所以 agent 维护布局，脚本维护数字。

**固定的看板结构：折、轮次、数据集。** 它适合启发这块看板的那个项目，却不适合大多数其他项目。积木能承载任何实验协议，积木表达不了的内容由采集脚本补上。
