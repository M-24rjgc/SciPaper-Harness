# Agent Note: 每次召回都遵从的知识图谱结果标记

Status: proposed

[English](2026-10-01-knowledge-graph-annotations.md) | 中文

## 问题

召回（recall）按共享词语为内置研究模式图谱（29,240 篇论文、318 个模式，每篇论文记录 5 篇最近邻论文）和项目自己的图谱排序，配置了嵌入端点时还按语义排序。阅读结果的人知道排序无从知道的事：这篇论文很重要，那篇针对的是另一种设定。这种判断没有地方记录，于是下一次召回又列出同样的论文，agent（智能体）既无法遵从这个判断，也说不清自己改动了什么。

## 提案

人和 agent 共用图谱上的标记。[knowledge-annotations.ts](../../../../packages/research/workbench/src/knowledge-annotations.ts) 包含存储和重排，二者都是纯代码，由知识引擎（`research-knowledge-provider`，`ctx.researchKnowledge`）调用。

- **标记**指明一个目标（`ai` 或 `project` 图谱中的一个模式或一篇论文，按其 id）、一个裁定（`pin` 或 `irrelevant`）、一条可选的单行理由（最多 280 个字符）、作者（`user` 或 `agent`）和时间。标记的 id 就是目标在图谱视图中的节点 id（`ai:paper:<id>`），因此一个目标只有一个标记，相反的裁定会替换它。
- **存储**是 `.research/kg/annotations.json`，内容为按 id 排序的 `{version: 1, annotations}`，最多 1,000 个标记、1 MiB。写入方持有该文件的 `withFileLock`，以原子重命名提交；读取方不加锁。再次设置相同的标记或删除不存在的标记都不写入。重建后的图谱若已没有某个标记的目标，该标记仍然保存，并报告为孤立（orphaned）。无法解析或含有格式错误记录的文件，给出能读出的标记，并为每个缺陷给出一条问题说明，前十条逐条列出、其余只计数；下一次修改先把该文件复制为 `annotations.json.<时间>.bak`，再重写它。更新的格式版本写成的文件既不遵从，也不重写。
- **重排**由 `applyAnnotations` 完成，它接收召回截断之前的完整融合排序。没有标记指向已加载图谱中的目标时，它原样返回前 `limit` 个候选。否则，每个列表先列出置顶项：查询召回到的按查询顺序，其余按时间从新到旧，最多五个；标为不相关的目标离开列表，若查询原本把它放在可见范围内，就连同理由列入 `skipped`；其余每个候选按"原位置 + 3 × penalty − 3 × boost"排序，相等时保持查询顺序，因此标记让一个结果下移不到六位。
- **权重**：论文标记对一篇论文的权重为 1 − Π(1 − 0.5ᵏ)，乘积取遍两者之间由记录的相似链接组成、长度 k ≤ 3 的所有简单路径，链接按两个方向读取；也就是每条链接以 0.5 的概率传递裁定时，裁定到达该论文的概率。模式标记对其每篇论文的权重为 0.5。同一裁定的多个标记以同样方式合并，低于 0.15 的权重视为没有。模式的权重是其论文权重的平均值，因此一篇被标记的论文对其模式的影响，与该模式有多大部分靠近它成正比。penalty 是不相关标记的权重，boost 是置顶标记的权重。
- **每一项都说明原因。** `why` 为 `pinned`（含 `recalled`）、`demoted` 或 `boosted`（移动的位数、penalty 与 boost、权重最大的标记及其关系、反方向上权重最大且计入的标记，以及作用于它的标记数），或 `unchanged`。关系为 `similar`（附链接数）、`in-pattern`，或 `members`（附到该模式最近一篇论文的链接数，以及标记触及该模式的论文数）。汇总统计已应用、置顶、跳过、下移、上移、孤立以及位于未加载图谱上的标记数，`describeAnnotations` 把汇总写成给 agent 的一段话。
- **开销。** `prepareAnnotationGraph` 为每个已解析的图谱构建无向链接数组、id 映射和模式成员（内置图谱用时 44–52 ms），存放在以图谱对象为键的 WeakMap 中，随已加载的图谱一起释放。同一结构还保存最近 2,000 个论文标记的扩散结果。含 1,000 个标记的一次召回首次耗时 29–34 ms，之后约 10 ms；100 个标记分别为 5 ms 和 1 ms。

召回、知识工具的标记操作和图谱视图另行接入本模块。

## 曾考虑的替代方案

**以标记为种子、在记录的链接上运行个性化 PageRank。** 它把一篇论文的质量分给邻居，而在这个图谱上，度数高的论文邻域反而更一致，因此它几乎分不开相关与不相关的直接邻居（一条链接处的 AUC 为 0.54，本方法为 0.71）。它的质量没有概率尺度（一、二、三条链接处为 0.15、0.02 和 0.00），以位数表示的上限需要再做一次校准；它也给不出可用于解释移动的链接数；在召回的候选中它触及 29 篇中的 25.8 篇，而挑出要移动的论文并不更准（0.512–0.516 对 0.514）。在评估套件自己的实现中，它每个标记耗时 8–9 ms，本方法为 1.4 ms。重启概率 0.5 的排序更差（AUC 0.688）。

**以最强的命中作为正种子的 PageRank。** 与被标记论文相连的 230 个候选中，228 个仍净下移：它几乎什么都不改变，而它改变的那一点，又是用人刚刚纠正过的排序去抵消人的裁定。

**基于向量的 Rocchio 式调整。** 内置图谱不附带向量，嵌入只针对模式文本、且只在配置了端点时才有。用 TF-IDF 向量时，每个候选都与被标记论文共享查询词，于是调整触及全部 29 个候选，挑选也更差（精确率 0.443；去掉查询词后为 0.405）。

**跳数衰减，或只在最短路径上做 noisy-OR。** 二者对同一距离上的论文一视同仁或几乎如此（一条链接处的 AUC 为 0.500），而两到四条路线会把同属该模式的比例从 0.42 提高到 0.67–0.84。

**Katz 游走计数。** 排序效果相当（AUC 0.721），但没有上界，会把折返的游走也计入，且需要一次变换才能成为有界的权重；所选权重以概率形式承载同样的路径计数。

**只移除被标记的目标。** 不相关论文附近的论文都不移动，于是标记了首个命中的人看到它的邻居仍在原处；它是场景表中的参照行。

**缩放融合分数而不是按位数移动。** 倒数排名分数很平（同一排序中第一位和第十位的分数为 1/61 和 1/70），把分数减半会让结果下降约六十位，无法让强匹配留在可见范围内。

## 待决问题

- 置顶项列在查询的 `limit` 之外，每个列表最多五个；所有者可能更希望它们占用查询的位置。
- 标记让不相关论文的直接邻居下移约一位，并在八篇论文的可见范围中替换四分之一篇论文；更强的移动会失去对前三的保证。
- agent 的标记与人的标记权重相同。
- 内置图谱上的标记不会作用于项目图谱中的同一篇论文，不相关标记也不改变新颖性检查。

## 验收标准

- 召回用 `readAnnotations` 读取标记，把完整的融合排序交给 `applyAnnotations`，并返回它给出的列表；没有标记时输出保持逐字节不变，评估套件的一致性测试在内置图谱上固定这一点。
- 知识工具通过 `setAnnotation` 和 `removeAnnotation` 设置和删除标记，输入由 `annotationInputSchema` 校验，在示例项目中拒绝；项目有标记时，召回结果带有 `why`、`skipped`、汇总和 `describeAnnotations` 写出的段落，并有一个录制会话快照固定这一输出。
- 图谱视图在节点上显示标记，并按节点 id 编辑标记。
- `knowledge-annotations.ts` 保持逐文件 100% 覆盖率，评估套件在 `RESEARCH_KG_EVAL=1` 下通过。

## 风险

- "同一模式"标签来自同样产生相似链接的聚类，这对图方法有利；词法余弦与之一致（rho 0.414），但它衡量的是共享词语，而不是人给出的理由。
- 各常数是在内置图谱上测得的。项目图谱有自己的链接，或者没有链接；没有链接时，标记只作用于它的目标和目标所属的模式。
- 内置图谱中的论文 id 有重复（三个 id、七个副本，其中两个 id 的副本归在不同模式下）；标记覆盖每一个副本，查询未召回的置顶项显示最后一个副本，也就是图谱为之记录了链接的那个。
