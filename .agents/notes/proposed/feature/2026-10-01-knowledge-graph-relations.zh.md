# Agent Note: 有依据的方法、任务、数据集、指标与论文关系图谱

Status: proposed

[English](2026-10-01-knowledge-graph-relations.md) | 中文

## 问题

知识图谱把论文连到它的模式、把模式连到它的领域，并记录哪些论文相似。它没有带类型的关系，所以无论是人还是 agent（智能体），都无法问两个方法之间是什么关系、哪个方法在哪个数据集上评测过、项目的文献还有什么没有测过。让语言模型随意填写的关系图谱也能回答这些问题，但给出的关系没人能核对。图谱只能收录以项目自身记录中的内容为依据的关系，在这些记录变化时随之失效，并且遵从人的更正。

## 提案

研究工作台新增三个模块，以纯代码的形式承载图谱，由研究服务、知识工具和「关系」视图调用：[knowledge-relations.ts](../../../../packages/research/workbench/src/knowledge-relations.ts)（模型、存储、实体合并识别、更正、陈旧判断与引文）、[knowledge-relations-grounding.ts](../../../../packages/research/workbench/src/knowledge-relations-grounding.ts)（依据规则及其使用的文本匹配）和 [knowledge-relations-queries.ts](../../../../packages/research/workbench/src/knowledge-relations-queries.ts)（邻域、路径和空白矩阵）。

- **实体**分为方法、任务、数据集、指标和论文。论文一定是项目的某条文献记录（`paper:<evidence id>`）；其余实体有一个规范名称和至多 16 个别名，id 为 `<kind>:<小写并以短横线连接的名称>`。
- **关系**有方向：`cites`（论文到论文）、`introduces`（论文到它提出的对象）、`is-a`、`extends`、`improves-on`、`compares-with`、`applied-to`（方法到任务）、`evaluated-on`（方法到数据集，可附带 32K 这样的设定）和 `measured-by`（到指标）。同一种类和同一有序端点对只有一条关系，关系至多带 12 条依据。
- **依据**是证据记录某一修订版中的一段引文（记录、修订版、定位和来源原话），或已完成的项目运行（运行、它收集到的指标记录、运行名称中分别指称两端的词，比较时还有基线运行），或一条 OpenAlex 或 Crossref 引用记录。API 中不存在没有依据的提议。
- **存储**是 `.research/kg/relations.json`，内容为按 id 排序的 `{version: 1, entities, relations, citations}`，至多 2,000 个实体、5,000 条关系、8 MiB。它沿用[标记注记](2026-10-01-knowledge-graph-annotations.zh.md)中标记文件的做法：用 zod 校验记录，写入时持锁并原子重命名，损坏的文件读出能读的部分，重写前先另存一份副本，更新格式版本的文件从不重写。每次编辑都是从已存图谱到新图谱的纯函数，所以重复提议不会改变任何东西。
- **陈旧状态在每次读取时推导**（`relationGraph`）。引文或运行依据的记录不在了、被记为陈旧，或修订版不是核对时的那一版，依据就过时了，这与声明使用的 `isOutdated` 判断相同；依赖“we”的依据，在它所依赖的提出关系不再有效时失效；论文记录不在了，引用就失效。关系在还有当前依据时为 `active`，剩余依据全部过时时为 `stale`，关系本身或其全部依据被驳回时为 `rejected`。`regroundRelations` 用新修订版重新核对引文，并把仍然成立的引文移到新修订版。
- **更正**可以驳回一条关系或其中一条依据（可附理由），也可以恢复。人的驳回对 agent 一直有效，直到人恢复它；agent 只能撤销自己的驳回。人提议一条已被驳回的关系，就会恢复它。被驳回的关系仍然保存，以便一直被遵从。

## 依据规则

引文在折叠后必须出现在所引修订版的某个可引用分块中，或跨越两个相邻分块。折叠包括兼容分解（连字、全角字符）、转为小写、去掉组合符号，以及去掉空白、各种短横线、软连字符、零宽字符和 Markdown 强调符号。因此 PDF 的断行连字和丢失或多出的空格不会妨碍匹配，而存下的引文是来源的原话。引文长度须在 4 个词（8 个汉字）到 500 个字符之间。带全文的文献记录必须在正文页中包含该引文：示例项目的 Longformer 记录带着一段属于另一篇作品的提供方摘要，只在那里出现的引文会被拒绝。BibTeX 分块永远不可引用，运行的指标以运行的形式引用。

必须由来源的原话（而不是提议者的话）在不同的词上分别指出两端：用名称、别名，或同一记录以 `long form (SF)` 或 `SF (long form)` 形式定义的缩写（Schwartz 与 Hearst 的匹配方法）。在通过有效的 `introduces` 关系提出某一端的那篇论文的引文中，“we”“our”或“this paper”可以指称这一端，依据会记录所依赖的提出关系。`introduces` 只能引用论文本身。名称按词元键匹配：词元键忽略大小写、重音、连字、空格和保守的复数形式，并在大小写变化处切分单词（`withFlashAttention`、`QAFACT EVAL`）；`TRUE`、`LED` 这样的短全大写名称只匹配大写写法。

| 种类 | 两端 | 要求 |
|---|---|---|
| introduces | 论文 → 方法、任务、数据集、指标 | 论文自己的记录；propose、introduce、present、call、refer to this model as |
| is-a | 同一种类 | is a、a kind of、such as、including、exemplified by、`X, a Y` |
| extends | 方法 → 方法 | extends、builds on、based on、principles of、variant |
| improves-on | 方法 → 方法 | outperforms、surpasses、better … than、improves on；前三个词内没有否定；改进的一方在该词之前，或在被动式（`outperformed by`、`被`）中在该词之后 |
| compares-with | 方法 → 方法 | compared、baseline、versus、against 或表示改进的词；或两个共享某项指标的运行 |
| applied-to | 方法 → 任务 | 两端都被指出 |
| evaluated-on | 方法 → 数据集 | evaluate、benchmark、results、achieves、accuracy、demonstrates 或表示改进的词；设定必须出现在引文中 |
| measured-by | 方法、任务、数据集 → 指标 | 两端都被指出；运行依据须是它记录过的指标 |

运行依据要求运行已完成、结果已收集且未陈旧，并且对每一端，运行名称或命令中有一个词是该端的某个名称键，或其某个名称中的实义词（如 `ruler-32k-dynamic` 中的 `dynamic`）。人的引文必须存在且至少有四个词；其余规则只作为警告随依据保存，因为一段话说了什么由人来判断。

## 引文

`createCitationFetcher(get, {pauseMs, sleep, now})` 以每次 50 篇论文向 OpenAlex 查询，先按 DOI 再按作品 id，只取 `id`、`doi` 和 `referenced_works`；对 OpenAlex 列出但没有参考文献的论文，再按 DOI 向 Crossref 查询。请求依次发出并有间隔（OpenAlex 在没有密钥时允许每秒十次）；与文献客户端一样，不发送电子邮件地址。`citationQueries` 列出缓存列表缺失或超过调用方给定时长的论文。`applyCitationWorks` 按论文和提供方缓存每份列表，并记录项目论文之间的每一次引用；它会重新匹配所有缓存列表，所以新导入的论文无需请求即可获得旧论文对它的引用。引用只能弱地说明两个方法之间的关系，所以引用依据的权重为 0.5。

## 查询

- **邻域**深度为 1 或 2：第一圈按关系置信度排序，第二圈按经由第一圈各节点的两段置信度乘积之和排序，至多 80 个节点、每个节点至多四条关系。布局提示给出每个节点所在的圈、它在圈上的位置（按种类、强度和名称；第二圈节点排在与它联系最强的第一圈父节点之下），以及 `core`：与中心一起构成最大且不小于 2 的 k-核的节点。
- **路径**：在由有效关系（除非排除，还包括陈旧关系）构成的无向图上求 Yen 的 k 条最短无环路径（k ≤ 5，至多 6 跳），每对节点之间取置信度最高的关系；每跳代价为 0.25 − ln(置信度)，每条支路用限制跳数的 Bellman–Ford 搜索。置信度是对关系各来源的 1 − Π(1 − w)（全文引文或运行 0.9，提供方摘要 0.8，项目文件 0.7，引用 0.5），陈旧时减半。每一跳都返回它的方向和权重最高的两条依据。
- **空白矩阵**列出方法与任务（`applied-to`）、数据集（`evaluated-on`）或设定的组合：每个单元格统计其依据支持该组合的不同文献记录、运行和项目文件，并计入行和列的 `is-a` 子类。没有依据时，它读取项目的段落（全文记录的正文页，否则为摘要，以及项目文件）：同一段落提到两者时为 `mentioned`，两者都被提到但从未出现在同一段落时为 `absent`，其中之一从未被提到时为 `uncovered`。被驳回的依据从不计入，单元格会报告被驳回的数量。

## 空白矩阵的措辞

矩阵描述的是项目的来源，而不是整个领域。视图标题写「本项目文献中的空白」，并注明其所依据的覆盖范围，如「6 篇全文、2 篇仅元数据」。各状态的措辞为：`reported`「本项目文献中有 N 篇报告」；`project-only`「仅见于本项目的实验或笔记」；`stale`「依据已更新，需重新核对」；`mentioned`「有 N 处同时提到，尚未核实」；`absent`「本项目文献中没有报告」；`uncovered`「本项目文献未涉及，结论前请先检索」。视图从不说「没人测过」或「领域空白」。

## 在示例项目上的评估

[knowledge-relations-eval.spec.ts](../../../../packages/research/workbench/tests/knowledge-relations-eval.spec.ts) 用 agent 会从两个示例项目中提出的关系，对照这些记录在 PDF 提取后留下的原样摘录逐一检验，并按其段落是否真的陈述了该关系加以标注。同样的提议对照完整记录，结果相同。

| 项目 | 提议 | 接受 | 其中未被陈述 | 拒绝 | 其中确被陈述 |
|---|---|---|---|---|---|
| Sparse attention scaling study | 61 | 43 | 2 | 18 | 2 |
| 长文摘要一致性评测 | 21 | 15 | 0 | 6 | 3 |

58 条被接受的关系中有 56 条确由其段落陈述（97%），61 条确被陈述的关系中有 56 条被接受（92%）。24 次拒绝都说明了要改什么：引文未找到并指出来源从何处与之不同（3 次：一次改写、一次引了另一篇论文的记录、一次 agent 漏掉了脚注标记 `QAGS,1 an`）、缺少该种类的提示词（4）、有一端未被指出（6）、只出现在提供方摘要中（1）、改进方向颠倒（1）、设定不在引文中（1）、提出关系引用了另一篇论文（1）、运行属于另一个方法（1）、运行未收集结果（1）、种类不符（2）、记录没有该修订版（1）、把引用当作引文提供（1）和只有三个词（1）。两次错误接受正是词汇规则看不到的：“Longformer's attention mechanism is a drop-in replacement for the standard self-attention”被当作 `is-a` 通过，“both Longformer and BigBird outperform models with smaller contexts”被当作二者之间的比较。五次错误拒绝分别是没有提示词地陈述了加速和 is-a、一处指代（“on this dataset”）、一处未点名的引用（“the entailment-based metrics of Laban et al.”）以及脚注标记。

OpenAlex 只为稀疏注意力项目 8 篇论文中的 2 篇列出参考文献（Longformer 53 篇、BigBird 111 篇；2024–2025 年的论文都没有，Crossref 对两个 ACL DOI 也没有），由此得到这两篇论文的互相引用。对于 31 篇摘要论文，它全部列出，得到它们之间的 168 次引用。

从项目自己的方法 `dynamic block selection` 到 `question answering` 的最佳路径有 5 跳，置信度 0.59：它与全注意力的运行比较、NSA 改进全注意力并且是一种稀疏注意力（NSA 第 1 页）、BigBird 是一种稀疏注意力并被用于问答（BigBird 第 1 页）；第三好的路径经过了一次错误接受。从 QAFactEval 到 FactCC 的路径依次是：AlignScore 与二者比较（0.81，前一跳经由“our baselines”）、二者都在 SummaC 基准上评测（0.729）、经由 SummaCConv 的同样路径（0.583），以及 QAFactEval 论文对 FactCC 论文的引用（0.405）。项目自己的提法 `block-sparse attention` 没有任何关系：它唯一的提议缺少 is-a 提示词。

在完整的稀疏注意力记录上（6 篇全文、2 篇仅元数据、5 个项目文件），方法与上下文长度的矩阵：

| 方法 | 32K | 64K | 128K |
|---|---|---|---|
| dynamic block selection | project-only（2 个运行） | absent | mentioned（1 处段落） |
| fixed block sparse attention | project-only（1 个运行） | uncovered | uncovered |
| full attention | project-only（1 个运行） | mentioned（4） | mentioned（3） |
| MoBA | mentioned（9） | mentioned（1） | reported（1 篇论文） |

对 64K 下的 dynamic block selection，矩阵给出的是本项目文献中没有论文报告，而原型的横幅声称的是几乎没人测过。

在一个有 157 个段落、84,615 个词元的全文项目上，61 次提议耗时 226 ms，段落索引 61–136 ms，两个空白矩阵 24–57 ms，五条路径 2–3 ms；五条路径的 JSON 为 11.6 KB，一个有 16 个节点和 18 条关系的邻域为 13.6 KB，一条带引文的关系在文件中约占一千字节。

## 曾考虑的替代方案

**由模型判断一段话是否支持该关系。** 它能接受改写，也能识别上面两次错误接受，但其判断不可复现，无法在人的视图中解释，每次提议都要一次模型调用，而且本身就是一个没有依据的判断；词汇规则可以用一段话说清，它会在哪里出错，评估都列出来了。

**对引文做模糊匹配（编辑距离）。** 它能接受漏掉的脚注标记，但也会接受改动过的数字或漏掉的“not”；折叠只去掉 PDF 提取引入的差异，拒绝信息会指出来源从何处与引文不同。

**在引文周围留一个上下文窗口**，允许第二端在窗口中被指出。分块按页划分时，窗口会让紧挨着某个点名句子的无关句子通过；要求两端名称都在引文中，会迫使提议者引用真正陈述该关系的句子，500 个字符足够容纳两句话。

**自动把缩写与其全称合并。** 缩写会冲突（NSA、SA、QA）；只有在所引记录定义了缩写时，缩写才算同一个实体，`mergeSuggestions` 列出缩写对和只差一个字母的名称对，供显式合并。

**用嵌入做实体合并识别。** 它会把项目视为不同的 `dynamic block selection` 和 `dynamic sparse attention` 合并在一起；合并识别仍按折叠后的键精确匹配，相似性只用于建议。

**用个性化 PageRank 或扩散权重回答“A 与 B 怎么连起来”。** 它们给节点排序，而不是给出解释；Yen 的路径把每个答案给成带依据的若干跳，对数代价让路径置信度等于每一跳都成立的概率。

**把陈旧状态存下来。** 存储的标志要求每个改动记录的写入方都同时更新关系文件；像证据图谱推导声明状态那样从修订版推导，可以只保留一个事实来源。

**把设定作为实体。** 上下文长度属于一次评测，而不属于某个方法或数据集；把设定放在 `evaluated-on` 依据上，可以保持二元关系模型，同时仍对照引文或运行核对它。

**用文献检索记录判断“从未检索过”。** 记录中不保存检索，而一次查询也说明不了读过哪些论文；项目的来源是否提到某个方法或某一列是可以观察的，并且能区分 `absent` 和 `uncovered`。

**用 SQLite 代替 JSON 文件。** 图谱至多几兆字节，每次查询都整体读取；JSON 文件沿用标记文件的做法，也不需要 schema 迁移。

## 对待决问题的决定

- 用户自己的引文保持较轻的规则：必须存在于所引的版本并含四个词，没满足的规则作为警告与依据一起存储。agent 的引文适用严格规则。
- agent 只能建议合并（`mergeSuggestions`）。合并是用户的命令，因为没有任何操作能撤销合并。
- 缓存的参考文献列表保留 30 天（`citationMaxAgeDays`），请求之间间隔 120 毫秒（`pauseMs`）。获取是向 OpenAlex 和 Crossref 发出的只读 GET，与文献检索相同，只作为用户的后台任务（`relations-citations`）运行，绝不由 agent 触发。
- 内置图谱的论文不是节点。
- 空白矩阵默认不按 `is-a` 子类型汇总，除非请求打开。
- 重新核对按需运行（`relations-reground`，用户的命令）；其间图谱读取会标出已过期的依据。
- 来自运行的 `measured-by` 依据只覆盖提案点名的那项指标。
- 无论自主度如何，agent 的提案都不经审核直接记录，附有原文和 `by: 'agent'`，用户可以否定。
## 验收标准

- 研究服务为图谱提供命令（读取、提议、驳回、恢复、合并、实体别名、引文、重新核对、邻域、路径、空白矩阵），用导出的 zod schema 校验输入，拒绝示例项目中的改动，并传入已加载证据文本的项目。
- 知识工具为 agent 提供 `relations-propose`、`relations-reject`、`relations-neighbourhood`、`relations-paths` 和 `relations-gaps`，工具说明中包含 `RELATION_GROUNDING_RULE`，结果中包含各描述函数的文本；一个录制会话快照固定一轮包含一次接受和一次拒绝的提议。
- 「关系」视图用布局提示绘制邻域，显示所选关系的依据并可「打开原文」，用「这条不对」驳回、用引文补一条关系，查找两个节点之间的路径，并用上面的措辞显示空白矩阵。
- 三个模块保持逐文件 100% 覆盖率，评估测试中的计数保持成立。

## 风险

- 词汇规则会接受用该种类提示词提到两端、却并未陈述该关系的句子（评估中 58 条里有 2 条），并拒绝通过指代或没有提示词陈述的关系（61 条里有 5 条）；补救办法是人的驳回和补充，提示词列表只有英文和中文。
- 引文证明的是记录说了什么，而不是这条记录就是那篇论文：仅见于摘要的规则只能识别一种已知的提供方错误，识别不了记录本身弄错的情况。
- 近期论文的引用覆盖很差（稀疏注意力项目中 8 篇只有 2 篇），所以恰恰在文献最新的地方缺少引用路径。
- `absent` 和 `mentioned` 取决于图谱中已有的名称和别名：只有中文名称的方法，在得到英文别名之前，对英文文献都是 `uncovered`。
- 合并无法撤销，而 agent 的合并会立即生效。
